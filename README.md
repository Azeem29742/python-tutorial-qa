# Python Tutorial QA

A question-answering API over the official [Python 3 Tutorial](https://docs.python.org/3/tutorial/). It retrieves tutorial passages locally, uses Google Gemini to draft an answer from those passages, and returns the source sections and URLs.

## Project layout

- `app/main.py` assembles the FastAPI application.
- `app/api/routes.py` defines request models and HTTP endpoints.
- `app/services/` contains retrieval, corpus loading, and Gemini answer generation.
- `app/ingestion/tutorial.py` downloads and parses every chapter linked from the official tutorial index.
- `app/evaluation/` contains the 20 fixed questions and benchmark runner.
- `scripts/` provides command-line entry points.
- `data/tutorial.json` is generated by ingestion and ignored by Git.
- `data/evaluation_results.json` contains the measured retrieval results and misses.
- `.env.example` shows the local Gemini configuration. Copy it to `.env` and add your key; `.env` is ignored by Git.

## Setup with uv

```powershell
uv sync
Copy-Item .env.example .env
```

Edit `.env` and replace the placeholder with your Google AI Studio key. Then run:

```powershell
uv run python scripts/ingest.py
uv run python scripts/evaluate.py
uv run uvicorn app.main:app --reload
```

Ingestion needs internet access and saves the current docs snapshot to `data/tutorial.json`. Open `http://127.0.0.1:8000/docs` to try `POST /ask`. The default model is `gemini-3.5-flash-lite`; change `GEMINI_MODEL` in `.env` to use another model available to your API key. If `GEMINI_API_KEY` is missing, the endpoint still returns retrieved passages and says generation is not configured.

Google's current Gemini API quickstart uses the `google-genai` SDK and Interactions API. The current pricing page lists a free tier for Gemini 3.8 Flash; quotas and availability are controlled by Google and can change. See the [official quickstart](https://ai.google.dev/gemini-api/docs/get-started) and [official pricing page](https://ai.google.dev/gemini-api/docs/pricing).

## Design choices

The retriever uses deterministic lexical matching, light word-form normalization, and stop-word removal. It chunks sections into 120-word passages and boosts exact matches in section titles. The answer prompt tells Gemini to use only retrieved evidence and abstain when the passages do not answer the question. Source passages are returned so grounding can be checked.

## Retrieval evaluation

The 20 questions and expected subsection titles are in `app/evaluation/questions.py`. Hit Rate@5 counts a question as a hit if its expected subsection appears among the top five distinct retrieved titles. The corpus contained 132 sections from 16 official tutorial pages, fetched on 20 October 2026.

| Chunk size | Title boost | Hits | Hit Rate@5 |
| ---: | ---: | ---: | ---: |
| 120 words | 0.0 | 16/20 | 80% |
| 120 words | 0.6 | 17/20 | 85% |
| 250 words | 0.0 | 15/20 | 75% |
| 250 words | 0.6 | 17/20 | 85% |
| 500 words | 0.6 | 17/20 | 85% |

At 120 words, adding title weighting improved Hit Rate@5 by 5 percentage points. Without title weighting, increasing chunk size from 120 to 250 words reduced it by 5 points. Full per-question results are in `data/evaluation_results.json`.

## Three observed retrieval misses

These questions were missed by the API's 120-word, 0.6-title-boost configuration:

1. **“What does the with statement do when opening a file?”** Expected `Predefined Clean-up Actions`. File-object and startup-file passages ranked higher; generic “file” overlap outweighed the cleanup concept.
2. **“How do I import a module?”** Expected `Modules`. `Importing * From a Package` and `The Module Search Path` ranked higher; the lexical scorer does not identify which related section answers this broad question.
3. **“Which module provides filesystem operations such as listing a directory?”** Expected `Operating system interface`. List-related passages ranked higher because the retriever matches shared words literally and does not connect “filesystem operations” with the `os` module.

## What I would improve next

Compare against BM25 and embeddings, tune abstention using questions whose answers are absent from the tutorial, and pin a dated docs snapshot for repeatable results. Evaluate answer faithfulness as well as retrieval.
